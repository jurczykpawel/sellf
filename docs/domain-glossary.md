# Sellf domain glossary

Use these terms in code, UI and discussion. English identifiers remain English;
Polish translations are UI labels for the same concepts.

| Canonical term | Definition | Code or schema evidence |
|---|---|---|
| API key | An owner's credential for scoped API calls; activation, rotation grace and permanent revocation jointly determine whether it works. | `public.api_keys`; `admin-panel/src/lib/api/api-key-status.ts` → `getApiKeyStatus` |
| Rotation grace period | A retired API key's limited period of continued use, unless revoked or expired. `is_active=false` denotes retirement; `rotation_grace_until` bounds continued use. | `public.api_keys.rotation_grace_until`; `public.verify_api_key` |
| Dispute | A Stripe payment dispute with its own processor status and outcome, reported independently of product licenses. | `public.payment_disputes`; `admin-panel/src/app/api/webhooks/stripe/dispute-handlers.ts` → `handleChargeDispute`, `dispute.created`, `dispute.closed` |
| Sellf order identity | The transaction UUID and seller-facing order number used to correlate payments, refunds and subscription invoices. `invoice.paid` carries `invoice.orderId/orderNumber`; refunds carry `payment.id/orderNumber`. Stripe identifiers retain their own fields. | `payment_transactions.id/order_number`; webhook payload builders |
| Refund | A return of a payment amount whose processor status is distinct from the payment status. | `public.payment_refunds`; `admin-panel/src/lib/refunds/payment-status.ts` |
| Retained revenue | Gross amount less refunds for completed and partially refunded orders, grouped by original currency in minor units. Fully refunded orders contribute zero. CSV exports keep amount and refunded amount separately for reconciliation. | `payment_transactions.amount/refunded_amount`; `get_detailed_revenue_stats`; `get_payment_summary`; payments stats API |
| Customer access value | Current product catalog prices grouped by their original currencies; granted access value, independent of payment revenue. | `UserWithAccess.product_access`; `AccessValue` |
| Refund status version | A stored observation version used to order and deduplicate a refund’s status notifications. | `public.payment_refund_events`; `refund.statusVersion` |
| Business event | A committed order, access, reservation, sales invoice, partner, refund request or catalogue change captured transactionally for signed webhook delivery. | `public.business_events`; `admin-panel/src/lib/services/business-events.ts` |
| Free grant context | Validated checkout answers stored before the sign-in email and bound to a verified buyer and product when free access is granted. | `public.free_grant_contexts`; `admin-panel/src/lib/services/free-grant-context.ts` |
| Suspended access | An inactive grant retained with its original identity and term while a payment dispute awaits resolution. Manual deletion or a full refund prevents its restoration. | `public.apply_payment_dispute`; `public.payment_disputes.account_access` |
| Free trial (okres próbny) | A fixed-price subscription starts with no charge for the configured number of elapsed 24-hour days; recurring billing begins when that period ends. The checkout date preview uses the buyer’s timezone; the persisted billing date is authoritative after signup. | `products.trial_days`; `subscriptions.trial_end`; `admin-panel/src/lib/checkout/trial-display.ts` |
| License issuance source | How a recorded license was issued: `purchase` (paid or free order), `manual` (admin panel) or `api` (API v1). Offline-signed licenses are never recorded. | `issued_licenses.issuance_source`; `admin-panel/src/lib/license-keys/request.ts` |
| License expiry notification | The single `license.expired` event for an active license past its expiry, marked so it is not repeated. | `issued_licenses.expiry_notified_at`; `public.capture_expired_licenses` |
| Paid cancellation deadline | Cancellation without a current-period refund retains existing access and invoice licenses until the paid invoice period ends; full or partial refunds after cancellation end them immediately. A full refund also ends an active subscription immediately; resuming it requires a new purchase. Unpaid terminal states still revoke. | `subscription-handlers.ts` → `applyCanceledSubscription`; `access_expires_at`; `issued_licenses.expires_at` |
| License revocation by dispute | A revocation whose recorded owner is the dispute that changed the license. A later manual or refund decision removes that ownership; won restores only licenses still owned by its dispute. | `issued_licenses.revoked_by_dispute_id`; `payment_disputes.revoked_license_ids` |
| License order reference | The immutable `order` claim in a signed license. Paid orders resolve the transaction UUID, Stripe session, PaymentIntent or invoice to the same Sellf order. Full refund, cancellation and dispute cover every main, bump and bundle license; free grants retain `free_<user>_<product>`. | `license_order_references`; `revoke_order_licenses` |
| Revocation reason (powód cofnięcia) | Why access or a license stopped working, sent to integrators next to the legacy origin `reason`: `refund`, `dispute`, `manual`, `subscription_cancelled`, `expired` (access past its term, or a subscription that ended unpaid). | `issued_licenses.revocation_reason`; `public.add_event_contract_fields`; `revocationReason` in `access.revoked`/`access.expired`/`license.*` |
| Renewal notice (zapowiedź odnowienia) | The `subscription.renewal_upcoming` warning, sent 3 days before renewal; an earlier Stripe `invoice.upcoming` is stored and emitted when due, never for a subscription no longer renewing. | `subscriptions.renewal_notice_at`; `public.capture_due_renewal_notices`; `RENEWAL_NOTICE_DAYS` |
| Cancel note | The administrator's own text for cancelling an unpaid transfer order, sent as `cancelReasonText` next to the `cancelReason` code. | `payment_transactions.cancel_note`; `public.cancel_unpaid_order` |
| Lead submission | An email request awaiting confirmation through its own magic link before product access and lead.captured. Retains the form locale independently of marketing consent. Distinct from a waitlist or purchase. | `public.lead_submissions`; `admin-panel/src/lib/leads/server.ts` → `leadSubmit`, `confirmLead` |
| Marketing consent | The server-recorded wording and version accepted with a lead submission, active after email confirmation. Distinct from cookie consent and mailing list membership. | `public.lead_submissions` → `marketing_consent`, `consent_text`, `confirmed_at` |
| Sales invoice (faktura sprzedaży) | A tax invoice issued for an order by the configured invoicing provider (Fakturownia), with its own attempt and status lifecycle. Distinct from a Stripe subscription invoice (`invoice.paid`). | `public.invoices`; `admin-panel/src/lib/invoicing/service.ts`; `invoicing.*` |
| Refund request (prośba o zwrot) | A buyer's request to be refunded, decided by the seller (approved, rejected or cancelled). Distinct from the refund itself, which is a money movement. | `public.refund_requests`; `refund_request.*` |
| Partner commission (prowizja partnera) | A partner's earning on a paid order, recorded as ledger entries (accrual, reversal); payable after `eligible_at`. | `public.affiliate_commissions`, `public.affiliate_ledger`; `commission.accrued`, `commission.reversed` |
| Partner payout (wypłata partnera) | A reservation of a partner's payable commissions that the owner then marks paid or cancels. Reservation is the approval point. | `public.affiliate_payouts`; `payout.reserved`, `payout.paid`, `payout.cancelled` |
| Sold-out session (wyprzedany termin) | An event session whose held (unexpired) and confirmed seats reached its capacity. | `public.product_sessions.capacity`; `public.capture_sold_out_event`; `product.sold_out` |
| Order number | A seller-facing sequential number of a payment transaction (from 1001), searchable as `1300` or `#1300` and used in direct links `/dashboard/payments?order=1300`. PL: „nr zamówienia”. | `public.payment_transactions.order_number`; `admin-panel/src/lib/payments/search.ts` → `parseOrderNumberQuery` |
| Orders list | Admin view of everything a customer obtained: paid order, bank transfer, free claim, manual grant, subscription and lead, paged with a cursor. PL: „Zamówienia” (zakładka Płatności). Read-only; access rows are classified by their grant source. | `admin-panel/src/lib/orders/merge.ts` → `mergeOrders`, `pageOrders`; `GET /api/admin/orders` |
| Grant source (źródło nadania) | How an access row was obtained, recorded once at insert by the granting path: `purchase`, `bundle`, `bank_transfer`, `subscription`, `free`, `manual`; `unknown` only for rows older than the column that no recorded fact explains. Never inferred from price. | `public.user_product_access.grant_source`; trigger `set_access_grant_source`; migration `20261110235906_release_2026_11_0_fulfillment_orders.sql` |
| Partial refund | A refund of less than the remaining refundable amount, entered in the refund dialog; the server re-checks the remaining amount. | `admin-panel/src/lib/refunds/refund-amount.ts` → `parseRefundAmountInput`; `admin-panel/src/lib/actions/payment.ts` → `processRefund` |
| Purchase source (źródło zakupu) | Where an order came from — UTM tags, referrer host, landing page, device, country — frozen once when the order becomes a purchase (paid, bank-transfer order, free grant); renewals inherit the first checkout's source. | `public.purchase_attribution`; `public.snapshot_purchase_attribution`; `admin-panel/src/lib/attribution/` |
| Touch (kontakt): first / last | A recorded visit with its marketing labels. Last touch = the visit that led to the purchase (always, from the checkout link); first touch = the first known visit (only with the visitor's analytics consent). | `purchase_attribution.last_*` / `first_*`; `admin-panel/src/lib/attribution/collect.ts` |
| Channel (kanał) | Classification of a touch (`email`, `paid_social`, `paid_search`, `organic_social`, `organic_search`, `referral`, `affiliate`, `direct`, `other`, `unknown`) by the seller's ordered channel rules; default explicit paid/email campaign rules precede click-id fallbacks, and a partner coupon always yields `affiliate`. | `public.attribution_channel_rules`; `public.classify_attribution_channel` |
| Click id retention | Seller-set number of days an ad click identifier (gclid, fbclid…) stays stored; kept only with marketing consent, then erased while its type remains. | `public.attribution_settings.click_id_retention_days`; `public.purge_attribution_click_ids` |
| Recorded attempt (zapisana próba) | A payment record created when a checkout starts, in any status. Funnel buckets: paid (completed, refunded, partially refunded, disputed), pending, abandoned, and other (awaiting bank transfer, cancelled); the buckets sum to the attempts. | `public.get_checkout_funnel`; `admin-panel/src/components/dashboard/CheckoutFunnel.tsx` |
| Add participants later (uzupełnię później) | Product checkout option on the participants module (`allow_later`): the buyer pays with an empty participant list, gets up to two reminder mails (24 h after purchase, 2 days before the event) with a signed link (`/order/:id/participants`) and saves the list once; saving emits `order.participants_updated`. The payments page lists orders still missing participants. | `checkout_profile.modules[participants].allow_later`; `public.submit_order_participants`; `public.list_orders_missing_participants`; `admin-panel/src/lib/orders/participants-service.ts` |
| Timed reservation (rezerwacja czasowa) | Unpaid event transfer order holding its seat and tier price until `release_at`; a reminder goes out at `reminder_at`. Seller-configured; regular products have none. | `payment_transactions.reminder_at/release_at`; `bank_transfer_config.reservation_*`; `public.release_unpaid_transfer` |
| Transfer declaration (zgłoszenie przelewu) | The buyer's one-time "I have sent the transfer" from the signed order link; extends the timed reservation and asks the seller to check the statement. | `payment_transactions.transfer_declared_at`; `public.declare_transfer`; `order.transfer_declared` |
| Invoice hold (faktura wystawiona, czeka na płatność) | An unpaid transfer order with an issued invoice: held without expiry; only cancellation (followed by a correction) releases it. | `payment_transactions.invoice_hold_at`; trigger `invoice_holds_transfer`; `order.invoice_issued` |
| Order reopening (przywrócenie zamówienia) | Administrator acceptance of a transfer received after cancellation, at the order price and possibly over the seat limit (`oversold`). | `payment_transactions.reopened_at`; `admin_bank_transfer_order(..., p_accept_cancelled)`; `order.reopened` |
| Pay link (link do zamówienia) | Signed 61-day link to the buyer's order page (status, transfer details, declaration) sent in mails and every `order.*` event as `payUrl`. | `admin-panel/src/lib/orders/transfer-token.ts` → `buildOrderPayLink` |
| Tax identifier type (typ identyfikatora podatkowego) | The rule a buyer's tax number follows, chosen by the company country: `pl_nip` (checksum), `eu_vat` (country prefix + per-country format, optional non-blocking VIES result) or `other` (any identifier outside the EU). | `order_details.buyer.tax_id_type/tax_id_country/tax_id_vies`; `admin-panel/src/lib/validation/tax-id.ts`; `invoice.taxIdType` |
| Guided tutorial (samouczek) | A clickable, step-by-step walkthrough of one admin screen (driver.js). Starts once on the administrator's first visit to the feature, then only on request from the help menu; "seen" is stored per user. Steps attach to `data-tour` markers; texts are in `messages/*.json` under `tutorials`. | `public.tutorial_progress`; `admin-panel/src/lib/tutorials/registry.ts` |
| Payment-received mail | The sign-in email a bank-transfer buyer receives once the administrator books the full amount; sent once per order and resumed by the scheduled recovery job if undelivered. | `public.payment_transactions.transfer_paid_mail_sent_at`; `admin-panel/src/lib/orders/transfer-mail.ts` |
| License key mail | The sign-in email that hands a buyer all license keys from one paid order, or the key after a free grant. The purchase confirmation reuses this delivery; keys are removed from account data once rendered. Pending deliveries check current licenses and access. | `admin-panel/src/lib/license-keys/license-mail.ts` |

## Buyer emails / Maile do kupujących

Transactional messages are delivered by the seller's webhook integration by default. `shop_config.supabase_buyer_emails` enables the optional Supabase Auth mail channel; existing installations keep it enabled on upgrade, new shops default to false. Authentication links remain active independently. `order.participants_needed` requests the missing participant list (stage 1 or 2) and carries a personal `reminder.participantsUrl`. `license.issued.licenseKey` is the delivery token; other license lifecycle events omit it. `purchase.completed` confirms receipt of payment, including bank transfers, and includes entitled event mail details in `buyerMail`. `order.paymentDeadline` is the effective transfer deadline (reservation release or normal due date).

Buyer event language (`customer.locale`): required `pl`/`en` on buyer webhook deliveries. Taken from the associated order (including its subscription), subscription, lead or saved license issuance language; free and manually issued licenses save the language used for their buyer mail. License lifecycle events include customer email, user id and locale. Manual issuance uses the latest known buyer language, then the submitted language and shop default; legacy records fall back to `shop_config.custom_settings.default_locale`, then the application default. A retry retains the stored language.

Guest order claims follow the linked transaction (or the legacy checkout session): refunded, disputed, cancelled and fully refunded payments grant no product or bump access. Completed and partially refunded orders retain their normal claim policy; transfer orders may grant access before settlement when configured.
